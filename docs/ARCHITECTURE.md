# 架构

## 设计原则

1. 模板是唯一业务来源，适配器只负责平台编译。
2. CLI 协调器是运行状态的唯一权威来源。
3. 规划、实现、验证与裁决通过机器角色 ID 隔离。
4. 所有状态变化写入追加式 JSONL 事件日志。
5. 提示词不能绕过状态、预算、审批和路径边界。

## 组件

- `@thearchy/core`：Schema、角色、风险、状态机、存储、Git 与安全。
- `@thearchy/adapter-codex`：生成 Codex 插件和 Skill。
- `@thearchy/adapter-claude`：生成 Claude Code插件、Agents 与命令。
- `thearchy-cli`：安装、协调、模板、报告和工作区接口。

## 状态数据与版本

运行快照当前为 `schemaVersion: 3`。读取 v1/v2 快照时自动迁移，并保留原始备份；未知版本进入只读恢复模式。

Git 项目默认使用 `.git/thearchy/runs/<run-id>`：

- `snapshot.json`：当前快照。
- `events.jsonl`：追加式审计日志。
- `.lock`：运行级互斥锁。

快照额外记录：

- 待处理与已解决的用户决策；
- 子 Agent 模型、推理强度、心跳和租约；
- 候选 worktree、验证产物和选择状态；
- 高风险操作请求和返回阶段。

无 Git 项目使用用户目录下的 `.thearchy/state`。

## 适配边界

宿主工具负责模型推理、子 Agent 和工具调用。CLI 不读取模型隐藏推理，只接收结构化产物路径、角色 ID 和审批命令。

当 `run next` 返回 `interaction` 时，宿主依次尝试 MCP 询问组件、原生可选项输入和结构化文本回退；未获得用户选择前不得继续。

## 精简治理拓扑

协调器采用三级自适应风险分流：

- 低风险 `auto` 任务直接进入轻量模式；
- 中风险 `auto` 任务通过询问组件确认轻量或完整模式；
- 高风险任务强制进入完整模式，显式轻量请求也不能覆盖。

轻量模式默认最多使用2个顺序执行的子 Agent：

1. 一个任务领域专家；
2. 一个独立验证 Agent，同时完成自动化检查和成果审查。

根主 Agent 负责路由、简要规划、派工和发布。轻量模式跳过独立方案裁决，但仍保留方案确认、风险操作审批和最终合并确认。

完整模式默认最多使用4个子 Agent：

1. 一个规划 Agent；
2. 一个在方案和成果阶段复用的独立裁决 Agent；
3. 一个任务领域专家；
4. 一个测试 Agent。

根主 Agent 负责路由、派工和发布。轻量模式的规划也由根主 Agent 完成。这样保留独立审查，同时避免为纯协调职责创建额外子 Agent。

协调器根据仓库、模板和标准化任务指纹复用尚未结束的运行。只有显式传入 `--allow-duplicate` 才能为相同任务创建第二个运行。

完整模式先完成测试 Agent验证，再由成果裁决 Agent读取测试产物进行最终裁决，避免并行执行导致证据尚未生成。默认完整模式预算为4个子 Agent、并发2个、10分钟活动执行时间。
